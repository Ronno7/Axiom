# Handoff

## Latest presentation update (2026-10-19)

Prototype now includes diegetic geometric engine exhaust (`ThrustDisplay` under
`AircraftVisual/Thrust`) and meta screen-edge damage pulses (`DamageFeedback`, bound by
`LevelUi`). See `Docs/UI.md` for tuning and verification. Both were inspected in Play Mode;
all 91 EditMode tests available before the controller update passed. No package versions
or gameplay rules were changed by the presentation work.

## Where things stand

M0–M3 are done: flight, combat, the full loop, menus and saved options. M4 (physical controller) is in
progress: the kit controller (v1) works with the LCD, and the cockpit box (v2) has its parts, wiring and
sketch, with bench testing under way. Progress and the session log are in `Docs/DEVELOPMENT_PLAN.md`;
read `README.md`, `Docs/DESIGN_BRIEF.md`, `FLIGHT.md`, `COMBAT.md` and `UI.md`, and
`Arduino/cockpit/README.md` for the controller. Develop in small, requested milestones.

The Unity project is the nested `Axiom` folder within the repository. Use Unity **6000.3.24f1**, URP
**17.3.0** and Input System **1.20.0**; API compatibility is .NET Framework (needed for System.IO.Ports).
Preserve the installed package versions, including the user's Unity MCP installation.

## Conventions

- Namespace remains `GeometricFlight`; the product name is Axiom.
- Forward is world +Z, vertical +Y, horizontal +X.
- Gameplay reads the abstract `FlightInputSource`; keyboard and controller supply the same snapshot.
- Keep visual banking below the player root so movement, collision and aiming stay stable.
- Preserve scene edits, `.meta` files and GUIDs. No runtime scene regeneration.
- Keep editor utilities in `Editor` and avoid import-time project-settings changes.
- Use a few understandable components; introduce patterns only for concrete needs.
- Keep docs lean. Never commit: the user commits everything.
